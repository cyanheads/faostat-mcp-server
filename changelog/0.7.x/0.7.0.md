# 0.7.0 — 2026-11-13

## Added

- **`faostat_query_observations` `offset` and `nextOffset`:** `offset` (0 to 100,000) picks the page's first row and `nextOffset` continues while rows remain, with or without DataCanvas. A page whose next page would start past 100,000 carries no `nextOffset`; its notice says to partition by year or codes. ([#52](https://github.com/cyanheads/faostat-mcp-server/issues/52))
- **`totalCountIsFloor`:** `totalCount` is exact up to 50,000 and on a match's last page; on any other page past 50,000 it reads 50,000 with `totalCountIsFloor: true`. ([#52](https://github.com/cyanheads/faostat-mcp-server/issues/52))
- **`faostat_commodity_profile` `ranking_elements`:** names the elements and units behind each ranking. ([#51](https://github.com/cyanheads/faostat-mcp-server/issues/51))
- **`years_behind` on every ranked row:** the ranking's latest year minus the row's `year`. A notice names rows behind it and the `year_start` that drops them. ([#50](https://github.com/cyanheads/faostat-mcp-server/issues/50))
- **Count inputs served at the cap:** `limit`, `top_n`, and `row_limit` above their cap are served at it, with `requested*` / `effective*` fields and a notice. Caps: `limit` 1000 on `faostat_query_observations`, 200 on `faostat_list_domains` and `faostat_resolve_codes`, 100 on `faostat_dataframe_describe`; `top_n` 50; `row_limit` the canvas row limit. `FAOSTAT_CLAMP_LIMITS=false` restores rejecting. An exact-code lookup (`faostat_resolve_codes`, `faostat_list_domains`) or a `name` lookup (`faostat_dataframe_describe`) returns its one match whatever `limit` says. ([#56](https://github.com/cyanheads/faostat-mcp-server/issues/56))

## Changed

- **Breaking: `faostat_dataframe_query` refuses a column alias (bare, double-quoted, or upper-case), CTE name, or table alias spelled like a DuckDB internal metadata view** such as `duckdb_tables` or `pg_tables`, with `system_catalog_access`. `SELECT area AS pg_tables FROM <staged table>` answered in 0.6.0; rename the alias, CTE, or table alias. The same spelling inside a string literal still answers.
- **`system_catalog_access` recovery** tells the caller to rename the alias, CTE, or table alias; it named only table references.
- **`faostat_query_observations` row order within a year** is the store's own order, so an `offset` walk neither repeats nor skips a row. For two or more `item_codes`, rows tied on year can come in a different order than in 0.6.0. ([#52](https://github.com/cyanheads/faostat-mcp-server/issues/52))
- **`canvas_disabled`** is no longer a `faostat_query_observations` reason: with DataCanvas off the tool pages by `offset`. ([#52](https://github.com/cyanheads/faostat-mcp-server/issues/52))
- **`pool_closed`** is a declared, retryable reason on `faostat_query_observations`, `faostat_commodity_profile`, and `faostat_resolve_codes` for a read the server ends because it is shutting down. ([#46](https://github.com/cyanheads/faostat-mcp-server/issues/46))
- **`initialize` carries `serverInfo.description`**, from `package.json` ([cyanheads/mcp-ts-core#683](https://github.com/cyanheads/mcp-ts-core/issues/683)); a non-`SELECT` statement's message reads `Canvas query must be SELECT.`
- **`faostat_dataframe_query`:** `range()` / `generate_series()` over constants and `SHOW <table>` answer, and `DESCRIBE` of a missing table reports `missing_table`; all were `invalid_sql`. ([cyanheads/mcp-ts-core#822](https://github.com/cyanheads/mcp-ts-core/issues/822), [cyanheads/mcp-ts-core#597](https://github.com/cyanheads/mcp-ts-core/issues/597))
- **`faostat_list_domains`:** an upstream HTTP failure's error data no longer carries `body` or `responseBody`; status fields, recovery hint, and text are unchanged. ([cyanheads/mcp-ts-core#590](https://github.com/cyanheads/mcp-ts-core/issues/590))
- **faostat-guide 1.1 → 1.2** and the server `instructions` cover `offset` paging, `years_behind`, and `ranking_elements`.

## Fixed

- **`faostat_commodity_profile` rankings read each country's rows once,** in one pass over the item's matched rows, so their plan no longer depends on which indexes the store's planner statistics cover. The `query_timeout` recovery now says bounding by year narrows the rankings. ([#59](https://github.com/cyanheads/faostat-mcp-server/issues/59))
- **Planner statistics are rebuilt when missing or not covering an index,** by `mirror:refresh` and by the first data read; only a store with no statistics was rebuilt, so a refresh that added an index on unchanged upstream data left it unanalyzed.
- **Live-animal items profile on Stocks and their trade quantity elements:** rankings and trend were empty and reported as complete. ([#51](https://github.com/cyanheads/faostat-mcp-server/issues/51))
- **`faostat_query_observations` `limit` is the page size in every state:** the inline page was cut at a 100,000-character budget whatever `limit` asked, leaving the rest only on the staged table, and with DataCanvas off a match over 50 rows failed with `canvas_disabled`. ([#52](https://github.com/cyanheads/faostat-mcp-server/issues/52))
- **`faostat_dataframe_query` `row_limit`:** the cap is the canvas row limit (`CANVAS_DEFAULT_ROW_LIMIT`, 10000 unless configured) and the default is the smaller of 1000 and that cap; a canvas limit below 1000 failed every call that omitted `row_limit`.
- **Concurrent first stagings share one canvas** (each minted its own, leaving all but one table unreachable without its `canvas_id`); describe and drop never create a canvas, and a replaced canvas's table records are purged. ([#58](https://github.com/cyanheads/faostat-mcp-server/issues/58), [cyanheads/mcp-ts-core#598](https://github.com/cyanheads/mcp-ts-core/issues/598))
- **A statistics build ended by server shutdown** logs no warning and spends no retry. ([#46](https://github.com/cyanheads/faostat-mcp-server/issues/46))
- **The scheduled refresh skips a domain another process is syncing,** and shutdown stops and awaits a refresh in flight before closing the stores.
- **A sync changes nothing in a store until it holds the sync lease,** publishes its completion and index revision together, and a stopped sync does not wait for the statistics build; a refresh refused because another process held the lease could already have deleted that store's rows. ([cyanheads/mcp-ts-core#517](https://github.com/cyanheads/mcp-ts-core/issues/517))
- **The profile's row-level pointer** (truncated or failed staging) names the domains and element codes the staged set was read from and the call's `year_start` / `year_end`; it pointed at every element of the item over every year.
- **Descriptions:** `faostat_dataframe_query` `sql` lists all 15 staged columns (10 before); `faostat_commodity_profile` `year_start` / `year_end` say the bounds apply to the rankings, the trend, and the staged rows; `faostat_dataframe_describe`'s empty-canvas notice names what stages a table in this release.
