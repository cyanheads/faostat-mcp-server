# 0.7.1 — 2026-11-19

## Added

- **M49 area codes:** `faostat_resolve_codes` area matches carry `m49_code` (a string with its leading zeros, dotted for the "excluding intra-trade" aggregates), and a new `m49_code` input looks up every area carrying one; beside `code` or on another dimension it fails `invalid_m49_selector`. `faostat_query_observations` rows carry `area_m49` in an `M49` column, and staged observation tables gain `area_m49`. ([#65](https://github.com/cyanheads/faostat-mcp-server/issues/65))
- **`faostat_commodity_profile` `trade_item_code`:** ranks `top_exporters`, `top_importers`, their units, and the staged TCL rows on a named TCL item, for crops traded mostly in processed form; `trade_item` echoes `{ code, name }`, and a code naming no TCL item fails `trade_item_not_found`. ([#66](https://github.com/cyanheads/faostat-mcp-server/issues/66))

## Changed

- **Staged profile tables:** `area_m49` sits before `domain`, so `domain` is one ordinal later; read columns by name. ([#65](https://github.com/cyanheads/faostat-mcp-server/issues/65))
- **`faostat_resolve_codes`:** a call with both an unknown domain and a query that holds no search term now reports `invalid_query` (it was `unknown_domain`). ([#67](https://github.com/cyanheads/faostat-mcp-server/issues/67))
- **`faostat_resolve_codes` listing notices** say the codes are listed rather than matched (`Listing item codes 1–50 of 301`), whether `query` is omitted, blank, or `*`. ([#67](https://github.com/cyanheads/faostat-mcp-server/issues/67))
- **`faostat_commodity_profile` no-trade notice:** when neither trade ranking has an element to rank, it points to `faostat_resolve_codes` on TCL for a `trade_item_code`, or, when a `trade_item_code` naming another item was given, names the TCL elements that item carries; a code equal to `item_code` gets the notice of the call without it. ([#66](https://github.com/cyanheads/faostat-mcp-server/issues/66))
- **Caller text named in notices and error messages** is quoted, with control characters escaped.
- **`faostat_resolve_codes` element no-match notice** names the item scope it applied.
- **`faostat_resolve_codes` item lookups** find a domain's distinct item codes with one index seek per code; on a domain without planner statistics the previous release read every entry of its item index.
- **Each distinct word of a query is searched once,** so a query that repeats a word can order the same matches differently.
- **Planner-statistics log warnings** are reworded.
- **faostat-guide 1.2 → 1.3** covers the new inputs.

## Fixed

- **A refresh removes the observations FAO dropped from a domain file,** so a completed refresh leaves the cube with the file's rows and `indexed_row_count` equal to the file's count; `mirror:refresh` prints the records applied and the rows removed per domain. A data file that carries no data rows removes nothing and logs one warning. The first refresh after upgrading re-downloads every synced domain once to stamp its rows, and domains stay queryable meanwhile. ([#63](https://github.com/cyanheads/faostat-mcp-server/issues/63))
- **Items that only a domain's data rows name now resolve:** FBS items listed nowhere else came back empty from `faostat_resolve_codes`. The next sync, including a refresh of an unchanged upstream, adds them. ([#64](https://github.com/cyanheads/faostat-mcp-server/issues/64))
- **Planner statistics are rebuilt after a sync whose build did not complete:** the stale statistics were kept and no read or unchanged refresh rebuilt them. No data read starts a build while another process's sync holds the store's lease. ([#60](https://github.com/cyanheads/faostat-mcp-server/issues/60))
- **Under Node, shutdown during a statistics build waits for the one statement the build is running,** not the rest of a whole-table `ANALYZE`: an index's `ANALYZE`, the area/year `CREATE INDEX` on a store that lacks that index, or a wait of up to the 5 s `busy_timeout` for another connection's write lock. The build it ends commits no statistics, and the next process builds them. ([#62](https://github.com/cyanheads/faostat-mcp-server/issues/62))
- **A `query` or `item_query` made only of quotes, parentheses, asterisks, and whitespace fails `invalid_query`;** the previous release answered the resolver with the whole unfiltered listing and the profile with `ambiguous_item` over every QCL item. A blank or `*` value reads as omitted: the resolver lists, and the profile falls back to `item_code`, else `missing_item`. A NUL separates words as the other control characters do, so `wheat` followed by a NUL returns Wheat and a lone NUL matches nothing (`no_match` on the profile), where the previous release failed any query holding a NUL with an internal error (-32603) that carried no `reason`. ([#67](https://github.com/cyanheads/faostat-mcp-server/issues/67))
- **`code_text` and `item_codes_text` are uppercased before lookup,** so `210400f` resolves to `210400F` in lookup, element scope, counts, and staging. ([#68](https://github.com/cyanheads/faostat-mcp-server/issues/68))
- **`faostat_commodity_profile` exact-label preference** compares `;` and `,` alike and treats control characters as word separators.
- **`faostat_resolve_codes` no-match recovery** names the selector the call used (`code`, `code_text`, `name_contains`); it told every caller to omit `query`.
- **`faostat_commodity_profile` notice for a selected trade domain with no completed sync** no longer says the mirror is already building it.
- **`faostat_commodity_profile` heading** shows an `item_query` that holds a control character quoted.

## Security

- **`faostat_resolve_codes` (`query`) and `faostat_commodity_profile` (`item_query`):** full-text search time now grows linearly with the query's length.
