# 0.2.5 — 2026-09-30

## Changed

- **Mirror reads run on a `node:worker_threads` pool** ([#3](https://github.com/cyanheads/faostat-mcp-server/issues/3)). Cube reads leave the serving thread (`read-pool.ts`, `read-worker.ts`, two workers), so a slow read no longer stalls every request, `/healthz` included.
- **`query_timeout`, a retryable per-call ceiling** ([#3](https://github.com/cyanheads/faostat-mcp-server/issues/3)). A call's mirror reads, queue wait included, past 45 s fail with `Timeout`; declared on `faostat_query_observations`, `faostat_commodity_profile`, and `faostat_resolve_codes`.
- **Query-planner statistics build in the background** ([#24](https://github.com/cyanheads/faostat-mcp-server/issues/24)). `ANALYZE` runs on the read pool and the first data read no longer waits for it; `mirror:refresh` also builds statistics for any domain that has none.
- **`runDomainSync`** fails with `Conflict` while a sync of the same domain is already running ([#24](https://github.com/cyanheads/faostat-mcp-server/issues/24)).
- **Describe-then-query pointers** ([#23](https://github.com/cyanheads/faostat-mcp-server/issues/23)). Every notice, field description, and tool description carrying a `canvas_id` names `faostat_dataframe_describe` ahead of `faostat_dataframe_query`.
- **`bun run test`** runs the suite under Bun, then under real Node via the new `test:node` script — the runtime the npm bin and `.mcpb` use ([#36](https://github.com/cyanheads/faostat-mcp-server/issues/36)). It fails when no real `node` is on `PATH`.
- **Docker image** installs production dependencies in a native-platform `deps` stage on `oven/bun:1.4.2`, so no stage runs Bun under QEMU; the unused `python3 make g++` toolchain is gone and `.dockerignore` excludes `.faostat-mirror/` and SQLite files.
- **Packaging** — new `audit:fix` script, npm `files` excludes `dist/*.mcpb`, `.mcpbignore` excludes `docs/idea.md` and `logs/`, and `framework-skills/` plus the framework scripts are synced to mcp-ts-core 0.13.10.

## Fixed

- **Staged `value` column keeps its fractions** ([#30](https://github.com/cyanheads/faostat-mcp-server/issues/30)). Staged tables use declared schemas (`OBSERVATION_TABLE_SCHEMA`, `PROFILE_TABLE_SCHEMA`) rather than types inferred from the preview rows, so `value` is always `DOUBLE`.
- **Unknown or expired `canvas_id` fails as `canvas_not_found`** ([#35](https://github.com/cyanheads/faostat-mcp-server/issues/35)) on `faostat_query_observations` (when the result stages) and `faostat_commodity_profile`, instead of degrading to an unstaged answer. The dataframe tools now surface their own declared recovery for it.
- **Staging no longer masks a failed mirror read** ([#3](https://github.com/cyanheads/faostat-mcp-server/issues/3)). A timed-out, cancelled, or crashed read fails the call rather than returning a truncated inline page.
- **`faostat_commodity_profile` notice states every staging outcome** ([#31](https://github.com/cyanheads/faostat-mcp-server/issues/31)) — staged table, fit inline, staging failure, or disabled canvas — and `format()` no longer advises enabling a canvas that is already on.
- **`faostat_commodity_profile` provenance** records `year_start`/`year_end`, the input names, in staged `query_params` ([#32](https://github.com/cyanheads/faostat-mcp-server/issues/32)).
- **`faostat_commodity_profile` with QCL unselected** fails with the declared `domain_not_indexed` (`NotFound`, not retryable) instead of a retryable `index_not_ready` ([#37](https://github.com/cyanheads/faostat-mcp-server/issues/37)).
- **Markdown table cells are escaped** ([#27](https://github.com/cyanheads/faostat-mcp-server/issues/27)). The observation and production-trend tables run labels, units, and flags through the shared `markdownCell()`.
- **Item-filtered observation reads seek the item index** ([#33](https://github.com/cyanheads/faostat-mcp-server/issues/33)). `ORDER BY +year` stops the planner from walking the whole element slice when `item_codes` is set.
- **`faostat_resolve_codes` domain scope under Node** ([#36](https://github.com/cyanheads/faostat-mcp-server/issues/36)). The FTS match is now scoped in JS; `better-sqlite3` binds JS numbers as `REAL`, which dropped the `rowid` scope and returned codes outside the domain.
- **Bulk-host errors are status-classified** ([#28](https://github.com/cyanheads/faostat-mcp-server/issues/28)) through `httpErrorFromResponse`, so a manifest 4xx is no longer retried as an outage. A permanent manifest status carries a `FAOSTAT_BULK_BASE_URL` recovery hint, which the mirror CLI scripts print.
