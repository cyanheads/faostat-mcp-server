# 0.2.4 — 2026-09-19

## Added

- **CodeQL analysis workflow** — scans `javascript-typescript` and `actions` on push/PR to `main` and weekly.

## Changed

- **`canvas_id` inputs validate format at the schema** on all four dataframe/canvas tools — `CanvasIdSchema` rejects a malformed token at argument validation instead of it reaching the handler as a canvas miss.
- **HTTP session mode is declared in code.** `createApp()` sets `sessionMode: 'stateless'` directly rather than relying on a deployment's `MCP_SESSION_MODE`; `.env.example` sets the same value.
- **DuckDB execution-time errors remap to `invalid_sql`** on `faostat_dataframe_query` (e.g. a `CAST` no row value can satisfy), keeping the engine's own recovery hint instead of surfacing an undeclared reason.
- **Mirror SQLite handles close on shutdown** via a new `teardown()` hook — the per-domain databases and the shared dimension database were never released otherwise.
- **Development skills moved from `skills/` to `framework-skills/`** so a plugin-installing agent isn't handed the server's own dev skills.
- Bun engine floor raised to `>=1.4.0`.

## Fixed

- **`faostat_dataframe_query` markdown cells escape backslashes before pipes** ([#26](https://github.com/cyanheads/faostat-mcp-server/issues/26)) — a value like `x\|y` no longer splits a table row in `content[]`; `structuredContent` was never affected.
- **`canvas_id` tool descriptions match actual reuse behavior** ([#25](https://github.com/cyanheads/faostat-mcp-server/issues/25)) — omitting it stages onto the session's canvas rather than promising a fresh one every call.

## Security

- **CodeQL alert [#1](https://github.com/cyanheads/faostat-mcp-server/security/code-scanning/1) (`js/incomplete-sanitization`)** fixed in `dataframe-query.tool.ts` — same root cause as #26.
