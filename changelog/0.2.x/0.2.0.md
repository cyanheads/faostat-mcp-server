# 0.2.0 — 2026-07-27

## Added

- **`faostat_commodity_profile` gains `production_trend`.** An inline year/value series — the same per-`(year, unit)` SQL aggregate that ranks producers, summed over every matching area and item — rendered on both `structuredContent` and `content[]`. ([#5](https://github.com/cyanheads/faostat-mcp-server/issues/5))
- **`faostat_commodity_profile` discloses item-resolution truncation.** New enrichment fields `resolvedItemMatches` (total items the `item_query` matched in QCL) and `itemsTruncated` (true when that total exceeds the 5-item profile cap) surface when a broad name like "milk" is narrowed, with a notice pointing at `faostat_resolve_codes` for the full list. ([#5](https://github.com/cyanheads/faostat-mcp-server/issues/5))
- **`faostat_commodity_profile` validates `year_start`/`year_end`.** A reversed range now throws the same `invalid_year_range` contract error `faostat_query_observations` declares, instead of resolving the commodity and returning an empty-looking profile. ([#17](https://github.com/cyanheads/faostat-mcp-server/issues/17))

## Changed

- **BREAKING: `top_producers` / `top_exporters` / `top_importers` rank per-country sums, not raw rows.** Each row is now the value summed across every resolved item for that country — grouped by `(area_code, unit)` so incomparable units are never added — taken at that country's own latest year with data rather than one year computed globally across the whole match. A country whose series ends earlier than others no longer drops out of the ranking, and a country matching several resolved items no longer appears once per item. ([#5](https://github.com/cyanheads/faostat-mcp-server/issues/5))
- **`truncated` and `trend_points` changed meaning.** `truncated` now describes only whether the staged canvas table hit the 50,000-row cap — the rankings and `production_trend` are exact SQL aggregates over the complete filtered match and are unaffected either way. `trend_points` now counts every observation aggregated into `production_trend`, not a capped row read.

## Fixed

- **Cold-but-selected TCL was reported as not configured.** `faostat_commodity_profile` now tells apart a trade domain that is selected but still finishing its initial sync (`isSelected` true, `ready` false) from one absent from `FAOSTAT_DOMAINS` entirely — the first case's notice says to wait and re-check `faostat_list_domains`, the second says to edit the config; the two were previously collapsed into one "not indexed" message. ([#19](https://github.com/cyanheads/faostat-mcp-server/issues/19))
- **The staged-set notice claimed trade data it omitted.** When TCL is unavailable, the notice now says the canvas table holds production rows only, instead of describing a "merged production + trade" set that was never assembled. ([#19](https://github.com/cyanheads/faostat-mcp-server/issues/19))
- **The fit-inline notice reached `content[]` but was withheld from the enrichment surface.** Both client surfaces now agree once the merged set fits inline without staging a canvas table, regardless of trade availability. ([#20](https://github.com/cyanheads/faostat-mcp-server/issues/20))

## Migration

`faostat_commodity_profile`'s ranked rows (`top_producers`, `top_exporters`, `top_importers`) drop the per-row `flag: string | null` field. Read `flags: string | null` instead — the distinct, comma-separated, sorted set of data-quality flags across the observations summed into that row, not one observation's flag. A consumer reading `.flag` now gets `undefined`.
