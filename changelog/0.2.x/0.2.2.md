# 0.2.2 — 2026-07-27

## Fixed

- **A failed `ANALYZE` is no longer memoized as success.** `ensureQueryStatistics()` previously marked a domain as analyzed before attempting the pass, so a transient failure (a writer holding the SQLite lock past `busy_timeout`) left that domain on the uninformed query plan for the rest of the process, even after the contention cleared. The outcome is now recorded only after the attempt: success settles the domain, failure leaves it eligible for a retry on the next read, bounded at three attempts per domain (`ANALYZE_MAX_ATTEMPTS`) so an obstruction that never clears — a read-only volume — can't re-run the pass on every query. `refreshQueryStatistics()` keeps its unconditional re-analyze after a sync applies rows. ([#21](https://github.com/cyanheads/faostat-mcp-server/issues/21))
- **`faostat_resolve_codes` no longer triggers the statistics gate.** `domainDimensionCodes()` read distinct dimension codes through the same `openDomain()` the four filtering/aggregating paths use, so a discovery call — the one an agent is most likely to make first — paid for an `ANALYZE` pass tens of seconds long on a large domain, serving a filter shape it doesn't use. `openDomain()` now opens the handle ungated; the gate moved to a new `openAnalyzedDomain()` wrapper used only by the paths the statistics actually serve. ([#22](https://github.com/cyanheads/faostat-mcp-server/issues/22))
