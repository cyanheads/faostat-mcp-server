# 0.1.11 — 2026-07-27

## Added

- **`faostat_list_domains` bounded retrieval.** New `code` input does an exact, case-insensitive domain lookup that outranks `topic` / `indexed_only`. New `offset` + `limit` (default 20, max 200) page the code-sorted match set; new enrichment fields `totalMatches` (the filtered set before paging) and `truncated` / `nextOffset` (present when more remain) disclose the cap and the exact next call. `totalCount` keeps its original meaning — whole-catalog size, independent of any filter. Every existing output field is unchanged and renders on both `structuredContent` and `content[]`. ([#16](https://github.com/cyanheads/faostat-mcp-server/issues/16))

## Fixed

- **`faostat_dataframe_describe` reported every staged column as `VARCHAR`.** `stageObservations()` synthesized `columnSchema` from the spill handle's column names, which carries no type information — every column read back as text regardless of what DuckDB actually registered. It now calls `instance.describe({ tableName })` once after a successful spill and persists the resolved schema, so integer codes and `year` report `BIGINT`, `value` reports `DOUBLE`, and text columns report `VARCHAR` on both client surfaces. ([#15](https://github.com/cyanheads/faostat-mcp-server/issues/15))
- **`.mcpb` bundle disabled every canvas tool.** `scripts/clean-mcpb.ts` strips `@duckdb/node-bindings-<platform>/` from a packed bundle to keep it portable and under the registry's 25 MB cap, but this server loads `@duckdb/node-api` as a direct dependency and defaults `CANVAS_PROVIDER_TYPE` to `duckdb` — so a bundle install shipped the DuckDB client with no platform binding, and `faostat_dataframe_query` / `faostat_dataframe_describe` failed outright while `faostat_query_observations` silently lost its spill path. `manifest.json` now pins `CANVAS_PROVIDER_TYPE=none` for bundle installs, so canvas-backed tools fail closed with the typed `canvas_disabled` contract error and its real recovery hint instead of a misdirecting `@duckdb/node-api` install message. ([#18](https://github.com/cyanheads/faostat-mcp-server/issues/18))
